# ИИгра онлайн

Мультиплеерная «Своя игра» про ИИ для трансляции на ~400 зрителей.
Ведущий открывает вопросы на одном экране (`/host`), зрители отвечают
со своих телефонов по ссылке/QR (`/play`) — без регистрации и аккаунтов.
Очки получает каждый, кто ответил верно. Отдельно есть соло-режим
(`/solo`) — пройти все 25 вопросов самому в любое время, без таймера,
с выдачей кода подтверждения в конце.

## Сейчас задеплоено на Render

- Прод: **https://iigra-online-quiz.onrender.com**
- Ведущий: https://iigra-online-quiz.onrender.com/host — ключ задан в
  переменной окружения `HOST_KEY` сервиса на Render (Dashboard →
  iigra-online-quiz → Environment); в репозитории и в этом файле он
  сознательно не хранится.
- Игроки (ссылка/QR): https://iigra-online-quiz.onrender.com/play
- Соло-режим: https://iigra-online-quiz.onrender.com/solo
- Проверка кода прохождения (тот же `HOST_KEY`): https://iigra-online-quiz.onrender.com/verify
- Тариф: **Free** — сервис засыпает после ~15 минут без запросов и
  просыпается ~30–50 секунд при первом заходе. **Откройте `/host` за
  5–10 минут до начала трансляции**, чтобы он был уже «тёплый» к
  эфиру. Код лежит в репозитории https://github.com/4god/iigra-online-quiz
  (публичный — доступ Render настроен на него напрямую; секретов в
  коде нет, `HOST_KEY` задан только в переменных окружения Render).
- Деплой не привязан к GitHub-вебхуку (сервис создан напрямую по URL
  репозитория, не через GitHub App), поэтому **автодеплоя на пуш нет**
  — после `git push` нужно вручную нажать Manual Deploy в
  [дашборде Render](https://dashboard.render.com/web/srv-db0ejvfavr4c73fbdetg)
  либо попросить это сделать меня.

## Как это устроено

- `server.py` — FastAPI-сервер: WebSocket (`/ws`) для живой игры и
  REST (`/api/solo/...`) для соло-режима; вся игра держится в памяти
  процесса.
- `questions.py` — 11 вариантов игры, в каждом 5 тем × 5 уровней
  (100–500 очков) = 25 вопросов, всего 275, у каждого 4 варианта ответа.
  Живая игра играет вариант 1 (меняется переменной окружения
  `LIVE_VARIANT`), в соло-режиме каждому игроку достаётся случайный.
- `public/host.html` — пульт ведущего: табло, QR-код для входа,
  живой счётчик ответивших, раскрытие ответа, лидерборд.
- `public/play.html` — экран игрока: имя → ожидание → вопрос с
  таймером → результат.
- `public/solo.html` — самостоятельное прохождение: доска без
  таймера, сразу видно верно/неверно, в конце — код подтверждения.
- `public/verify.html` — инструмент для организаторов: ввести ключ
  ведущего и код зрителя, увидеть имя/результат/время прохождения.
- `game_state.json` — очки и использованные вопросы живой игры.
- `solo_state.json` — соло-попытки и выданные коды прохождения.

Оба файла состояния переживают перезапуск сервера (кроме вопроса,
открытого в момент рестарта живой игры — он сбрасывается).

Один процесс спокойно держит несколько сотен одновременных
WebSocket-подключений — для 400 зрителей хватит самого дешёвого
тарифа (512 МБ–1 ГБ RAM, 1 vCPU).

## Соло-режим и коды подтверждения

Любой зритель может пройти игру самостоятельно по ссылке `/solo` —
без таймера, в своём темпе. Правильность каждого ответа проверяется
на сервере (не в браузере), так что результат нельзя подделать через
консоль разработчика. После 25-го вопроса сервер выдаёт короткий код
вида `A1B2-C3D4` и запоминает его вместе с именем, итоговым счётом и
временем прохождения в `solo_state.json`.

Чтобы подтвердить, что конкретный человек прошёл игру — откройте
`/verify`, введите `HOST_KEY` и код, который он показывает. Это REST
API (`POST /api/verify`), так что проверку легко встроить и в другой
процесс (например, сверку при выдаче призов), если понадобится.

## Запуск локально

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
HOST_KEY=мойключ python3 -m uvicorn server:app --host 0.0.0.0 --port 8000
```

Откройте `http://localhost:8000/host` (введите `HOST_KEY`) и
`http://localhost:8000/play` на телефоне/другой вкладке.

Переменные окружения:

- `HOST_KEY` — ключ ведущего. Если не задать, сервер сам сгенерирует
  случайный и выведет в консоль при старте. **Ключ вводится прямо на
  странице `/host`, а не в адресной строке** — это специально, чтобы
  его не было видно при демонстрации экрана.
- `QUESTION_SECONDS` — сколько секунд даётся на вопрос (по умолчанию 20).

## Деплой для трансляции

Нужен обычный Python-хостинг с поддержкой WebSocket (подойдёт почти
любой PaaS). Проще всего — **Render** или **Railway**:

1. Залейте эту папку в репозиторий на GitHub.
2. На [render.com](https://render.com) → New → Web Service → подключите
   репозиторий. Render сам увидит `requirements.txt` и `Procfile`.
3. В Environment Variables задайте `HOST_KEY` (свой секретный ключ) и,
   при желании, `QUESTION_SECONDS`.
4. После деплоя получите публичный адрес вида
   `https://ваше-приложение.onrender.com`.
   - Ведущий открывает `.../host` и вводит `HOST_KEY`.
   - Зрителям показываете QR-код с пульта ведущего — он уже ведёт на
     `.../play` на вашем реальном домене.

Railway, Fly.io или собственный VPS работают по той же схеме
(`pip install -r requirements.txt`, затем `uvicorn server:app --host
0.0.0.0 --port $PORT`).

### Перед эфиром

- Откройте `/host` заранее и проверьте, что ключ подходит (заодно
  «разбудит» сервис на free-тарифе).
- Прогоните 1–2 тестовых вопроса с коллегой, зашедшим на `/play`.
- Нажмите «Начать заново» на пульте, чтобы сбросить тестовые очки
  (на проде уже есть один тестовый игрок с 500 очками — моя проверка
  после деплоя) и начать с чистого счёта.
- Поставьте `QUESTION_SECONDS` с запасом: на трансляции у зрителей
  всегда есть небольшая задержка видео/звука относительно общего экрана.

## Если нужна версия без зрителей (офлайн, один экран)

В папке на уровень выше (`../index.html`) лежит автономная версия
той же игры в виде одного HTML-файла — без сервера, для игры в
одной комнате с command-командами за столом.
