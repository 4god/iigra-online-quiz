# ИИгра

«Своя игра» про искусственный интеллект для онлайн-трансляции на ~1000 игроков.

| Адрес | Для кого |
|---|---|
| `/` | Игроки: регистрация, игра, чат, самостоятельные варианты. Это единственная ссылка, которую видят зрители (её же показывает QR на пульте). |
| `/host` | Ведущий: голосования, вопросы, модерация чата, итоги, настройки. Вход по ключу `HOST_KEY`. |
| `/verify` | Организаторы: проверка кода приза (тот же `HOST_KEY`). |

**Как запустить — в [GUIDE.md](GUIDE.md):** игра на одном экране, игра в зале с телефонами и отдельное примечание про онлайн-трансляцию и хостинг.

## Как проходит игра

1. **Регистрация.** Игрок открывает ссылку и придумывает логин и пароль. Имя, почта и телефон не нужны.
   - Логин: 3–20 символов (буквы, цифры, точка, дефис, подчёркивание), уникален без учёта регистра. Мат и служебные слова вроде «ведущий» и «admin» запрещены.
   - Логин виден другим игрокам в таблице лидеров и в чате.
   - Сервер закрепляет за игроком уникальный 6-значный ID, по нему выдаются призы.
   - Войти с любого устройства можно по логину или ID и паролю. Восстановить пароль нельзя.
   - Регистрироваться можно заранее, до начала трансляции.
2. **Голосование.** Ведущий нажимает «Начать голосование». Игроки выбирают плитку на своём экране и могут передумать. Проценты обновляются у всех в реальном времени. «Завершить голосование» подсвечивает победителя; при равенстве голосов победитель выбирается случайно. Голосование можно и не устраивать: ведущий в любой момент сам кликает по плитке.
3. **Вопрос.** Ведущий кликает плитку. Вопрос с четырьмя вариантами сразу появляется у всех. Игрок выбирает вариант и нажимает «Ответить»; после этого ответ не меняется. На ответ даётся `QUESTION_SECONDS` секунд (по умолчанию 30). Таймер серверный и не зависит от часов на телефоне.
4. **Ответ.** «Показать ответ» сразу подсвечивает правильный вариант и показывает, сколько людей выбрало каждый. Очки получает каждый, кто ответил верно. Таблица лидеров и место каждого игрока обновляются мгновенно.
   - При равенстве очков выше тот, кто суммарно быстрее отвечал правильно.
5. **Финал.** После последнего вопроса через 8 секунд у всех автоматически открывается итоговая таблица. Кнопка «Показать итоги» завершает игру досрочно.

**Чат.**
- Общий для всех, писать можно раз в N секунд (по умолчанию 5).
- Общий потолок — 15 сообщений в секунду на весь чат.
- Мат заменяется звёздочками автоматически.
- На пульте при наведении на сообщение — «Удалить» и «Мут» (мут также удаляет все сообщения игрока).
- В настройках: выключить чат, поменять интервал, снять мут.

## Самостоятельные варианты и призы

- **Как открыть.** В настройках пульта переключатель «Самостоятельные варианты». После этого у игроков появляется вкладка «Варианты» с 11 вариантами по 25 вопросов (`questions.py`).
- **Прохождение.** Без таймера. Каждый вариант на аккаунт проходится один раз, ответы проверяются на сервере.
- **Код приза.** После 25-го вопроса игрок получает код вида `KHYT-VRM2`. Код привязан к его ID и всегда виден в списке вариантов.
- **Проверка кода.** На `/verify` видно ID, вариант, счёт, дату и сколько вариантов этот игрок прошёл всего.
- **Выгрузки.** В настройках пульта можно скачать CSV со всеми кодами и CSV с итоговым рейтингом трансляции.

**Пасхалка: ML-хардкор.** Во вкладке «Варианты» 5 быстрых нажатий на логотип открывают 12-й вариант для data scientist'ов и ML-инженеров. Пока он открыт, страница становится красной. Коды за него помечены как «ML-хардкор».

## Вопросы

Вопросы хранятся в CSV-таблицах, которые редактируются в Excel. Код для этого трогать не нужно, подробно — в [GUIDE.md](GUIDE.md#вопросы-правка-в-excel-без-кода).

- `questions.csv` — 11 самостоятельных вариантов и пасхальный `ML`.
- `live_questions.csv` — уникальный набор трансляции. **Не хранится в репозитории** (файл в `.gitignore`). На сервер его кладут файлом или переменной `LIVE_QUESTIONS` (base64 от содержимого CSV).
- `python3 tools/check_questions.py` проверяет обе таблицы.
- `python3 tools/build_offline.py` переносит варианты в `offline/index.html`.

## Переменные окружения

| Переменная | Что делает |
|---|---|
| `HOST_KEY` | Ключ ведущего и организаторов. Без него генерируется случайный и печатается в лог. |
| `LIVE_QUESTIONS` | Набор вопросов трансляции: base64 от `live_questions.csv` (см. выше). |
| `LIVE_OPENS_AT` | С какого момента игроки могут присоединиться к трансляции, ISO-формат. По умолчанию `2026-11-12T00:00:00+03:00`. До этого сервер отклоняет голоса, ответы и чат; регистрироваться можно. |
| `LIVE_VARIANT` | Если вопросов трансляции нет, какой из обычных вариантов играть (по умолчанию 1). |
| `QUESTION_SECONDS` | Время на ответ, по умолчанию 30. |
| `DATA_DIR` | Папка для базы `iigra.db` (аккаунты, очки, коды). На Render это должен быть persistent disk, иначе база стирается при каждом деплое. |
| `REGISTER_LIMIT` | Регистраций в минуту с одного IP (по умолчанию 60 — офисы сидят за одним адресом). |

## Нагрузка

`tools/load_test.py` гоняет N виртуальных игроков: регистрация → голосование → вопрос → 200 сообщений в чат → раскрытие. Результат на 1000 игроков локально:

| Событие | 99% игроков получили за |
|---|---|
| Открытие вопроса | 47 мс |
| Сообщения чата | 157 мс |
| Результат и место после раскрытия | 79 мс |

Раунд нагружает сервер примерно на 9% одного ядра Mac, память — около 115 МБ.

На виртуальной машине Yandex Cloud (2 vCPU, 4 ГБ, через HTTPS и Caddy) 1000 игроков подключились за 9 с без отказов:

| Событие | 99% игроков получили за |
|---|---|
| Открытие вопроса | 110 мс |
| Сообщения чата | 250 мс |
| Результат и место после раскрытия | 120 мс |

Сервер во время раунда загружен на 10–40% одного ядра, память — около 110 МБ. Регистрация 1000 человек за 10 с загружает оба ядра (хеширование паролей).

Если гонять тест с домашнего компьютера, часть соединений может не открыться из-за лимита NAT роутера (около 1000 соединений). Тест покажет их отдельной строкой.

**Требования к серверу:**
- Нужен 1–2 vCPU и диск, который переживает перезапуски.
- Бесплатный Render не годится: 0,1 CPU, засыпает, а при засыпании стирает базу.
- Рекомендуемый вариант — виртуальная машина в Yandex Cloud на стартовом гранте, разворачивается скриптом `deploy/setup_vm.sh` (см. [GUIDE.md](GUIDE.md#примечание-онлайн-трансляция)).
- Запасной вариант — Render Starter или Standard с persistent disk для `DATA_DIR`.

## Перед эфиром

1. За 15 минут открыть `/host` и проверить, что нет жёлтого предупреждения про вопросы.
2. Прогнать вопрос с парой коллег. Потом «Настройки → Сбросить игру» (подтверждение словом «СБРОС»).
3. Убедиться, что «Самостоятельные варианты» выключены (их включают после эфира).
4. Во время эфира **не деплоить**. Рестарт сервера не теряет аккаунты и очки, но открытый в этот момент вопрос пропадёт, и у всех будет пауза на переподключение.

## Локальный запуск и тесты

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
HOST_KEY=test123 python3 -m uvicorn server:app --port 8765
python3 tools/e2e_test.py http://127.0.0.1:8765 test123          # полный сценарий
pip install aiohttp && python3 tools/load_test.py http://127.0.0.1:8765 test123 1000
```

Для нагрузочного теста запускайте сервер с `REGISTER_LIMIT=100000`.

`offline/index.html` — автономная версия для игры в одной комнате на одном экране, без сервера и без призов.
